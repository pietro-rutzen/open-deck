## Verification and handoff

The audio callback accepts a one-shot request at a block boundary and writes 2,048 pre-fader stereo samples into preallocated per-deck storage. It never waits for the display. The desktop command consumes one completed block and rearms the next. A hidden display can leave at most one final capture. The browser limits requests to about 15 Hz per selected, visible, active deck. Only Spectrum requests a windowed FFT. Stereo power combines both channels, including opposite-phase signals.

- Audio suite passed 98 tests. Regression fixtures compare master and headphone samples bit for bit, validate the pre-fader tap, and interrupt a capture across track replacement and device recreation.
- Desktop analysis tests checked tone frequency, dB level, antiphase stereo, bass trace duration at three device rates, silence and a lower Nyquist limit. Frontend typecheck and tests passed.
- macOS WebKit with simulated input checked all three widgets, idle defaults, deck isolation, slot changes, restoring a selection and resizing. command_audio_review independently reviewed the mailbox and callback path.
- Local offline benchmark using two playing decks, 48 kHz and 256 frames per block: median 167.75 µs off versus 170.08 µs on; p95 195.79 versus 198.58 µs. Separately, off-thread analysis plus JSON with all meters took 387 µs median, 452 µs p95 per requested deck snapshot in this debug build.
