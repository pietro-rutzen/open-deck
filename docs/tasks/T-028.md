# T028 — Bound deck decoding during rapid LOAD

2026-11-04. Owner root/backend; independent reviewer load_admission_review. Baseline aefba51 + preserved T025–T027 work. Claims: new src-tauri/src/deck_decode_worker.rs, load_track integration in lib.rs, task/progress/handoff docs. No audio callback changes.

- [x] One active deck decode/analysis job; at most one pending request per deck.
- [x] Generation-guarded submission and completion; queued stale/ejected requests skip decoding.
- [x] Round-robin service across decks, latest waiting request replaces older pending work.
- [x] Job panic cannot permanently kill decoder; current request publishes error.
- [x] Regression tests and desktop build pass: 129 native tests; one known local Trash case excluded.
- [x] Independent backend implementation review: no blockers.

Tradeoff: active decode is not preempted; a very large/slow file delays later requests on all decks. This bounds job concurrency, not individual file size, analysis memory, library-analysis workers or the upstream engine channel. Worker creation failure is cached and requires relaunch; it occurs before loading status. Existing tracks keep playing while decoding. No guarantee of callback installation from enqueue/publication.

Worker lives for process lifetime. See handoff for commands, build warning and scope. No hardware pass claimed.

Status: done for scoped concurrency fix; final test addition independently reviewed. Hardware endurance remains a separate open release gate.
