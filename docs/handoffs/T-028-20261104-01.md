2026-11-04 Europe/Helsinki. Owner root/backend, reviewer load_admission_review. Baseline aefba51 plus preserved T025–T027 changes. No commit/push. Existing lib.rs.orig untouched.

New deck_decode_worker.rs owns one process-lifetime worker with a fixed latest pending slot for each of NUM_DECKS. Round-robin dequeue happens under a short mutex; jobs execute unlocked. load_track obtains worker before publishing loading; submits under DeckLoads::commit and checks generation before decode. Existing post-decode and publication guards remain. Replaced pending closures are dropped on the calling control thread, never the audio callback. Panics publish latest-only errors and cannot terminate the worker.

Limits: no preemption of current decode/analysis, no individual-file byte cap, no bounding of library analysis or engine upstream messages. A slow current job delays other decks. Failed initial worker creation is cached until relaunch. Existing playback does not run on this worker. This is bounded decode concurrency, not a complete process-memory or hardware reliability guarantee.
